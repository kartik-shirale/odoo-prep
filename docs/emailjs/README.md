# EmailJS OTP template

Use this single template for signup verification and password recovery.

1. Create an EmailJS email template and paste `otp-template.html` into its HTML/code editor.
2. Set these template fields and save:

| Field | Value |
| --- | --- |
| Subject | `Your odoo code to {{purpose}}` |
| To Email | `{{to_email}}` |
| To Name | `{{name}}` |
| From Name | `odoo` |
| From Email | Use the default sender of your connected email service |
| Reply To | Leave empty, or use your own support email |

The connected provider must be authorized to send as the selected From Email.
Do not put the recipient address in From Email.

3. Set `EMAILJS_TEMPLATE_ID` to this template's ID in `apps/core/.env`.
4. Confirm EMAILJS_SERVICE_ID is the connected service, EMAILJS_PUBLIC_KEY is
   your account public key, and EMAILJS_PRIVATE_KEY is its private key.
5. Enable API requests for non-browser applications in Account > Security.
   If private-key authorization is enabled, use its matching private key.
6. Restart your core process after editing .env. Retry signup with the same
   email and original password, or sign in to the unverified account and resend OTP.

The backend supplies all template parameters:

```json
{
  "to_email": "recipient@example.com",
  "name": "Alice",
  "otp": "123456",
  "expiry_minutes": 5,
  "purpose": "verify your email"
}
```

For password recovery, purpose becomes `reset your password`. Actual codes are
cryptographically generated by core; never hardcode the preview code above.

EmailJS references: [REST send](https://www.emailjs.com/docs/rest-api/send/),
[server SDK and security setup](https://github.com/emailjs-com/emailjs-nodejs).

## Delivery errors

A 503 EMAIL_DELIVERY_FAILED means delivery failed, not that the database is
unmigrated. In development the toast now identifies recognized provider errors:
server requests disabled, missing recipient, rejected keys, invalid template,
mail-provider authorization, and limits. Production keeps the message generic.
Unknown provider responses still need investigation in the EmailJS dashboard;
keys and raw provider response bodies are never logged.

Unverified signup can be retried using its original password. It resends the code
without overwriting the stored account. Verified accounts still return 409.
Failed delivery does not consume the daily successful-email allowance.

The signed-out session check can return 401 because no refresh cookie exists.
Login 401 means the email/password did not match; use the original signup
password or the password-reset flow. Do not bypass verification or change
password hashes to silence these responses.
